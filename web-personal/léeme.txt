2. Estructura del proyecto y contenido de las carpetas
- index.html: Portada y presentación principal.
- about.html: Trayectoria, aficiones, galería y recursos multimedia propios (vídeo con subtítulos y audios con transcripción).
- projects.html: Catálogo interactivo de proyectos con filtrado por categoría y tecnologías.
- cv.html: Currículum vitae estructurado (experiencia, formación, certificaciones y referencias) con enlace al PDF.
- contact.html: Formulario de contacto con validación y retroalimentación, canales de contacto y disponibilidad.
- search.html: Buscador interno del sitio (resultados, resaltado de términos, sugerencias de corrección).
- help.html: Ayuda y accesibilidad: cómo navegar, cómo buscar, atajos de teclado, declaración de accesibilidad, idiomas, preguntas frecuentes e informe de problemas.
- sitemap.html: Mapa del sitio con todas las páginas y secciones.
- sitemap.xml: Mapa del sitio para buscadores, con alternativas hreflang.
- en/: Versión completa en inglés de todas las páginas anteriores (index, about, projects, cv, contact, search, help, sitemap). Comparte los mismos CSS, JS y recursos.
- assets/css/: Hojas de estilo CSS3 modulares.
  - base.css: Variables globales (Custom Properties), reset, enlace "saltar al contenido", migas de pan, formularios, bloques desplegables y componentes base.
  - layout.css: Estilos estructurales comunes (cabecera con menú responsive, buscador y selector de idioma; pie de página con enlaces de utilidad, redes sociales y fecha de actualización).
  - index.css, about.css, projects.css, cv.css, contact.css, search.css, help.css, sitemap.css: Estilos propios de cada página.
- assets/js/: Scripts JavaScript nativos (ES6+), todos cargados con defer.
  - nav.js: Menú de navegación móvil (aria-expanded, aria-controls, cierre con Escape) y enlace "saltar al contenido".
  - projects.js: Filtrado de proyectos por data-category con aria-pressed y anuncio del resultado en una región aria-live.
  - contact.js: Validación del formulario de contacto con mensajes de error por campo (aria-invalid, role="alert"), contador de caracteres y confirmación; prepara el correo mediante mailto.
  - search.js: Buscador del sitio. Normaliza mayúsculas y acentos, puntúa por título/palabras clave/cuerpo, tolera erratas (distancia de Levenshtein), resalta coincidencias y propone correcciones ("¿Quisiste decir…?").
  - search-index.js: Índice de búsqueda generado automáticamente (no editar a mano).
- assets/img/: Fotografías y capturas optimizadas (JPEG redimensionado), logotipos vectoriales (SVG) y favicon.svg.
- assets/audio/: Archivos de audio propios integrados con controles nativos en about.html.
- assets/video/: Vídeo demostrativo (f1.mp4) y sus subtítulos WebVTT (f1.es.vtt, f1.en.vtt).
- assets/cv_raul_antuna.pdf: Currículum en PDF descargable.
- tools/build-search-index.py: Script opcional (Python 3, sin dependencias) que regenera assets/js/search-index.js a partir del contenido de las páginas.
- léeme.txt: Este documento explicativo.

En la raíz del repositorio se incluye además 404.html, la página de error personalizada que GitHub Pages sirve cuando una URL no existe, con buscador y enlaces a todas las secciones.


3. Procedimiento de despliegue de la aplicación
Al ser una aplicación web estática pura (HTML5, CSS3 y JavaScript nativo), no requiere ningún proceso de compilación, transpilación ni instalación de dependencias en el servidor.
Para desplegar la aplicación:
1. Copiar la carpeta 'web-personal' completa al directorio servido por el servidor web (por ejemplo, en la ruta /var/www/html/web-personal/ de un servidor Apache o Nginx).
2. Asegurar que los ficheros cuentan con permisos de lectura para el servidor web.
3. Acceder mediante el navegador web a la dirección configurada en el servidor.

Si se modifica el contenido de alguna página, conviene regenerar el índice del buscador ejecutando desde la carpeta web-personal:
    python3 tools/build-search-index.py
y actualizar la fecha de "Última actualización" del pie de página.

5. Explicaciones y consideraciones específicas
Para este trabajo he utilizado exclusivamente HTML5, CSS3 y JavaScript nativo (Vanilla), prescindiendo por completo de frameworks (como React, Angular o Vue) y librerías CSS (como Tailwind o Bootstrap). Esta elección responde a la necesidad de garantizar el estricto cumplimiento de los estándares web fijados por el W3C:

- HTML5 Semántico: Toda la maquetación se apoya en etiquetas semánticas con significado estructural (header, nav, main, section, article, figure, time, address, details, footer) evitando el uso abusivo de divs o spans genéricos. Se mantiene una jerarquía coherente de encabezados (un único h1 por página), cada región (landmark) tiene una etiqueta única y se incorporan atributos ARIA para maximizar la accesibilidad.
- CSS3 Modular y Accesible: Se organizan las hojas de estilo de manera desacoplada y se utilizan variables CSS para mantener la coherencia cromática y tipográfica. La maquetación se basa en CSS Grid y Flexbox junto con media queries con unidades relativas (rem). Todas las reglas definen simultáneamente color y background-color y la paleta se ha ajustado para que todos los textos superen el contraste 4,5:1 exigido por WCAG 2.1 AA. Se respeta la preferencia "prefers-reduced-motion".
- JavaScript no bloqueante y progresivo: Los scripts se cargan de forma diferida mediante el atributo defer. Todo el contenido, la navegación y el formulario funcionan sin JavaScript; el buscador y el filtrado de proyectos lo mejoran de forma progresiva.
- Usabilidad: menú con página activa marcada, migas de pan en todas las páginas interiores, mapa del sitio, página de ayuda, buscador interno, página 404 propia, enlaces a redes sociales en el pie de todas las páginas y fecha de última actualización.
- Internacionalización: el sitio está disponible en español e inglés. Cada página enlaza con su equivalente en el otro idioma (atributos hreflang y lang) y las etiquetas <link rel="alternate" hreflang> informan a buscadores y navegadores.
- Multimedia accesible: el vídeo incluye pistas de subtítulos descriptivos en español e inglés (WebVTT) y una descripción textual; cada audio incluye su transcripción desplegable.
- Rendimiento: las imágenes se han redimensionado y comprimido (la galería pasa de 13 MB a menos de 0,5 MB), se usa loading="lazy" en las imágenes fuera de la primera pantalla y fetchpriority="high" en la imagen principal de la portada.
