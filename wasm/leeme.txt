2. Estructura del proyecto y contenido de las carpetas
- ejemplo.html: Interfaz visual del banco de pruebas (benchmark). Estructura HTML5 semántica (header, main, section, menu, form, output, etc.) con diseño accesible y modo oscuro.
- ejemplo.css: Estilos visuales responsive de la aplicación, validados sin advertencias.
- ejemplo.wat: Código fuente de los algoritmos en WebAssembly Text Format (WAT). Contiene las implementaciones de los algoritmos y los bucles de repetición inlined para benchmarking.
- ejemplo.wasm: Módulo binario compilado a partir de ejemplo.wat (659 bytes).
- ejemplo.js: Script que realiza la carga e instanciación del módulo WASM, implementa las versiones equivalentes en JavaScript nativo, gestiona los eventos de la interfaz y mide tiempos con performance.now().
- build.js: Script en Node.js que compila ejemplo.wat a ejemplo.wasm utilizando la librería 'wabt'.
- leeme.txt / léeme.txt: Este documento explicativo.


3. Procedimiento de despliegue de la aplicación
1. Si se modifica el archivo WAT, compilar el binario WASM ejecutando:
   node build.js
2. Copiar los archivos del proyecto al directorio servido por el servidor web (/var/www/html/wasm/).
3. La aplicación debe ser servida obligatoriamente a través de un servidor HTTP/HTTPS (por ejemplo Apache o Nginx). El método estándar WebAssembly.instantiateStreaming() requiere que el servidor sirva el archivo .wasm con la cabecera Content-Type 'application/wasm' y no permite la ejecución bajo el protocolo local 'file://' debido a las restricciones de seguridad del navegador.
4. Acceder en el navegador a la URL apuntando al archivo 'ejemplo.html' (puesto que este trabajo no utiliza el nombre por defecto index.html).

5. Explicaciones y consideraciones específicas
El proyecto realiza una evaluación comparativa de rendimiento y consumo entre WebAssembly y JavaScript nativo mediante tres algoritmos matemáticos:

1. Factorial de 64 bits (n!):
   - Evalúa aritmética entera de 64 bits.
   - WASM utiliza el tipo primitivo nativo 'i64', que se ejecuta en un solo ciclo de instrucción en registros de 64 bits del procesador.
   - En JavaScript se evalúa frente a 'BigInt' (la única representación entera exacta de 64 bits en JS), demostrando la sobrecarga que supone alojar objetos en el heap frente a operar directamente en registros de CPU. WASM resulta entre 10x y 20x más rápido.

2. Coseno por Serie de Taylor:
   - Aproximación de cos(x) calculando 15 términos mediante sumas, multiplicaciones y divisiones continuas en coma flotante de doble precisión (f64 / IEEE-754 de 64 bits), igualando la precisión de Math.cos(x).
   - Demuestra el rendimiento uniforme y determinista de WASM frente a los floats de JS.

3. Test de primalidad (32 bits):
   - Comprobación de números primos grandes mediante bifurcaciones condicionales y operaciones de módulo/resto (i32.rem_u en WASM frente al operador % en JS).

Criterios de benchmarking aplicados:
- Bucles inlined dentro de cada entorno para evitar el sobrecoste de frontera (boundary crossing) en cada iteración y evitar sesgos de inlining del compilador JIT.
- Fase de calentamiento (warmup) para permitir que los motores JIT estabilicen optimizaciones y que el compilador WASM del navegador ejecute el código en su nivel de compilación óptimo.
